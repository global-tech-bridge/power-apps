# テスト仕様書

要件定義 17章「受入条件」に1対1で対応させたテストケース。
**開発・テストでは実顧客情報を使わない**（要件定義 15.3）。
顧客名は `テスト太郎`、メールアドレスは自分または共有テスト用アドレスを使う。

結果欄は実施時に記入する。

## A. 基本機能（要件定義 17.1）

## E. エラー処理（要件定義 17.5）

意図的に失敗させて確認する。

| # | ケース | 失敗のさせ方 | 期待結果 | 結果 |
|---|---|---|---|---|
| E-1 | PDF生成の失敗 | `DocTemplates` のテンプレートを一時的にリネーム | エラー画面になり、**完了画面には行かない**。コード `E-FLOW-040` | |
| E-2 | メール送信の失敗 | 顧客メールを存在しないドメインにする | エラー画面。`Status` が `Sent` にならない。コード `E-FLOW-060` | |
| E-3 | エラーの記録 | E-1 の後に `SignatureCases` を確認 | `Status` = `Error`、`ErrorCode` / `ErrorMessage` / `FlowRunId` が入っている | |
| E-4 | 利用者向けメッセージ | E-1 のエラー画面 | 失敗した工程が日本語で分かる。例外文や個人情報は出ていない | |
| E-5 | 管理者の調査情報 | E-1 のエラー画面（管理者アカウント） | エラーコード・文書番号・レコードID・受付キー・発生日時・フロー実行IDが揃っている | |
| E-6 | 再実行の冪等性（PDF） | E-1 のテンプレートを戻して「もう一度送信する」 | 成功して完了画面へ。**文書番号は変わらない** | |
| E-7 | 再実行の冪等性（レコード） | E-6 の後に `SignatureCases` を確認 | レコードが1件だけ（重複していない） | |
| E-8 | 再実行の冪等性（PDF重複） | E-6 の後に `SignatureDocs` を確認 | PDFが1つだけ | |
| E-9 | メール失敗からの再実行 | E-2 のメールアドレスを直す → 一覧 → 該当案件 → ドラフトではないので詳細画面。**エラー画面からの再実行のみが正しい経路**。E-2 の直後に再実行する | メールだけ送られ、PDFは作り直されない | |
| E-10 | 確認文面マスタなし | `ConsentMaster` の `IsActive` を全部いいえにする | 入力画面に赤い警告が出て署名へ進めない | |
| E-11 | 二重送信の防止 | 確認ダイアログの「送信する」を素早く2回押す | 処理中オーバーレイで操作がブロックされ、1件しか作られない | |
| E-12 | 通信断 | 送信中に機内モードにする | エラー画面になり、通信回復後の再実行で完了できる | |
