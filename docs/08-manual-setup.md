# 画面だけで構築する手順（CLI を使わない）

`pac` CLI も PnP.PowerShell も使わず、ブラウザの画面操作だけで構築する手順。
[01 デプロイ手順](01-deployment.md) の「方法B」を全部書き出したもので、
このファイル1本で SharePoint とアプリの構築が完結する。

作業量の目安。

| 工程 | 内容 | 目安 |
|---|---|---|
| Part 1 | SharePoint リスト7つ（**計70列**）とライブラリ4つ | 30〜45分（方法A）／60〜90分（方法B） |
| Part 2 | 初期データの投入（確認文面・管理者・テンプレート） | 10分 |
| Part 3 | Power Apps の取り込み（6画面・197コントロール） | 40〜60分 |
| Part 4 | Power Automate フロー3つ | 90〜120分 |

Part 4 だけは別ファイル（[flows/](../flows/)）にある。**フローを先に作ってから
Part 3 をやる**ほうが手戻りがない（アプリがフローを参照するため）。

# Part 1. SharePoint リストとライブラリを作る

## 1-1. サイトを作る

1. SharePoint のスタート画面 → **＋ サイトの作成** → **チーム サイト**
2. サイト名: `YAJ整備キャンセル料確認書`（URL は `yaj-cancelfee` など）
3. プライバシーの設定: **プライベート**
   顧客名・メールアドレス・電話番号・署名画像を扱うため、
   既定で全社が見える設定にはしない（要件定義 15.3）

## 1-2. リストと列を作る

作る対象は次の7リスト・計70列。**列名・リスト名は英語のまま**にする（理由は後述）。

| # | リスト名 | 列数 | 用途 |
|---:|---|---:|---|
| 1 | `SignatureCases` | 34 | 署名案件（本体） |
| 2 | `OrgMaster` | 7 | 組織マスタ |
| 3 | `ConsentMaster` | 9 | 確認文面マスタ |
| 4 | `AppAdmins` | 4 | 管理者 |
| 5 | `SendLog` | 8 | メール送信履歴 |
| 6 | `AuditLog` | 7 | 監査ログ |
| 7 | `DocumentNumberCounter` | 1 | 文書番号の採番カウンタ |

作り方は2通りある。**方法Aを推奨する。**

### 方法A（推奨）: Excel から取り込んで列をまとめて作る

SharePoint の **＋新規 → リスト → Excel から** は、取り込んだ表のヘッダーから列を作る。
これを使うと、70列のうち **68列がウィザードで作られ、手作業は2列だけ**になる
（`SignatureCases.Operator` と `DocumentNumberCounter.LastNumber`）。

取り込み用のファイルは [`data/import/`](../data/import/) に用意してある。

| 順 | リスト | 取り込むファイル | 備考 |
|---:|---|---|---|
| 1 | `OrgMaster` | [`data/import/OrgMaster.xlsx`](../data/import/OrgMaster.xlsx) | **列と実データ105件が同時に入る**。Part 2-1 は不要になる |
| 2 | `SignatureCases` | [`data/import/schema/SignatureCases.xlsx`](../data/import/schema/SignatureCases.xlsx) | 33列。サンプル行6件は取り込み後に削除 |
| 3 | `ConsentMaster` | [`data/import/schema/ConsentMaster.xlsx`](../data/import/schema/ConsentMaster.xlsx) | 9列。サンプル行1件 |
| 4 | `AppAdmins` | [`data/import/schema/AppAdmins.xlsx`](../data/import/schema/AppAdmins.xlsx) | 4列。サンプル行1件 |
| 5 | `SendLog` | [`data/import/schema/SendLog.xlsx`](../data/import/schema/SendLog.xlsx) | 8列。サンプル行2件 |
| 6 | `AuditLog` | [`data/import/schema/AuditLog.xlsx`](../data/import/schema/AuditLog.xlsx) | 7列。サンプル行4件 |
| 7 | `DocumentNumberCounter` | （なし） | 作る列が `LastNumber`（数値）1つだけなので、空白のリストから手で作る |

#### 手順（1リストにつき同じ操作）

1. サイトのホーム → **＋ 新規** → **リスト** → **Excel から**
2. 上表のファイルをアップロードする（表が1つだけなので自動で選ばれる）
3. **列マッピング画面で、列の種類を1つずつ確認する。** ここが唯一の要注意点。
   選ぶ種類は [`data/import/schema/README.md`](../data/import/schema/README.md) に
   リストごとの表がある
4. リスト名に上表のリスト名を**そのまま**入力して **作成**
5. **取り込み後の手当てをする**（次項）

#### なぜサンプル行が入っているのか

ウィザードは**データから列の種類を推測する**ため、ヘッダーだけの空ファイルでは
全部が「1行テキスト」になってしまう。そこで型が分かる値を入れたサンプル行を付けている。

さらに、**選択肢列の選択肢はデータに出てきた値から作られる**。そのため
`SignatureCases` には `Status` の6つの選択肢すべてが1回は登場するよう
6行分のサンプルを入れてある（`MaintenanceType` の3つもこの6行に含まれる）。

サンプル行は1列目のテキスト列に `★取込後に削除★` と入っているので、
取り込み後にその行を選んで削除する。

#### 取り込み後の手当て

ウィザードで設定できない項目がある。
**[`data/import/schema/README.md`](../data/import/schema/README.md) が
リストごとのチェックリストになっている**ので、それを見ながら消していく。
内容は次の6種類。

| 種類 | 手当て |
|---|---|
| 複数行テキスト（7列） | 種類を **複数行テキスト** に変更し、**リッチ テキストを いいえ** にする。既定のままだと確認文面に HTML タグが混ざって PDF に出る |
| 日付と時刻（8列） | **含める内容 → 日付と時刻**。「日付のみ」だと署名日時の時刻が消える |
| 数値（5列） | 小数点以下の桁数を **0** にする |
| 選択肢（5列） | **「値を手動で追加できる」を いいえ**。選択肢が全部揃っているかも確認する |
| はい/いいえ（4列） | `IsActive` は既定値を **はい**、`NoSerialNo` は **いいえ** にする |
| `SignatureCases.Operator` | **ユーザー列はウィザードで作れない。** 手作業で「ユーザーまたはグループ」列（複数選択: いいえ）として追加する |

必須にする列は `SignatureCases.CustomerName` の1つだけ。

> **`Body` 列（確認文面の本文）について**
> ウィザードでは1行テキストとして作られるので、必ず **複数行テキストに変更する**。
> 1行テキストのままだと255字で切れ、確認文面が途中で失われる。
> 種類の変更ができない環境では、その列を削除して手作業で作り直す。

### 方法B: 空白のリストから1列ずつ作る

ウィザードの型推測を信用したくない場合、または方法Aで作った列の設定を
直すほうが面倒に感じる場合はこちら。

1. サイトのホーム → **＋ 新規** → **リスト** → **空白のリスト**
2. 上表のリスト名を**そのまま**入れて **作成**
3. **[02 SharePoint データ設計](02-sharepoint-schema.md) の表がそのままチェックリスト。**
   リストごとに、表の上から順に列を作る
   1. リストを開く → 一番右の **＋**（列の追加）
   2. 種類を選ぶ（表の「画面で選ぶ種類」の列）
   3. **名前** に表の列名を入力（**英語のまま**）
   4. **詳細オプション** を開き、表の「画面での追加設定」のとおりに設定
   5. 「既定のビューに追加する」は**外す**
   6. **保存**

#### 種類ごとの注意

| 種類 | 詰まりやすいところ |
|---|---|
| 複数行テキスト | 詳細オプションで **リッチ テキストを使用する → いいえ**。ここを既定のままにすると、確認文面に HTML タグが混ざって PDF に出る |
| 選択肢 | 選択肢の値を1行ずつ入力し、**「値を手動で追加できる」を いいえ** にする。`Status` は `Draft` `Signed` `PdfCreated` `Stored` `Sent` `Error` の6つを**英語のまま**入れる（画面の日本語表示はアプリ側で対応付けている） |
| 日付と時刻 | **含める内容 → 日付と時刻**。「日付のみ」にすると署名日時の時刻が消える |
| はい/いいえ | `IsActive` は**既定値を「はい」**にする。これをやると Part 2 のデータ投入で `IsActive` 列を省略できる |
| ユーザーまたはグループ | `Operator` のみ。複数選択は **いいえ** |
| 数値 | 小数点以下の桁数を **0** にする |

## 1-3. 列名とリスト名を英語にする理由

SharePoint は列を日本語名で作ると、内部名が `_x9867__x5ba2__x540d_` のような
エスケープ文字列になる。Power Automate の OData フィルター、Word テンプレートの
差し込み、REST 呼び出しはすべて内部名を使うため、日本語名にすると
**フローの式が読めなくなり保守できない**。画面上の日本語ラベルは
Power Apps 側のラベルで与えているので、SharePoint 側を日本語にする必要はない。

リスト名も同じで、Power Fx はリストを表示名で参照している。日本語名にすると
アプリの数式（`Patch(SignatureCases, ...)` など）が全部エラーになる。

> 一度作った列の名前をあとで変えても、内部名は最初の名前のまま残る。
> つまり**最初に英語で作ることだけが正解**で、日本語で作ってから直しても手遅れ。
> 間違えた場合は列を削除して作り直す。

### `Title` 列について

`Title` は SharePoint が最初から持っている必須列なので、作成しない。
`SignatureCases` では文書番号が入る（フローが設定する）。
`DocumentNumberCounter` では日付キー `yyyyMMdd` が入る。

方法Aの取り込みファイルには、この衝突を避けるため **`Title` 列を入れていない**
（`OrgMaster.xlsx` は拠点コードを `Title` に入れる設計なので例外的に含めている）。

分かりやすくしたい場合は、リストの設定 → `Title` 列 → 説明に
「文書番号（フローが採番して設定する）」などと入れておく。

## 1-4. インデックスを設定する

[02 SharePoint データ設計](02-sharepoint-schema.md) の表で「索引」が ○ の列。
全部で25列ある。

| リスト | 索引を作る列 |
|---|---|
| `SignatureCases`（12） | `DocumentNo` `CustomerName` `BranchName` `BlockName` `SiteName` `SiteCode` `Status` `SignedAt` `OperatorEmail` `OperatorName` `RegisteredAt` `ClientRequestId` |
| `OrgMaster`（3） | `BranchName` `BlockName` `SiteCode` |
| `ConsentMaster`（2） | `ConsentId` `EffectiveFrom` |
| `AppAdmins`（1） | `UserEmail` |
| `SendLog`（3） | `CaseId` `DocumentNo` `SentAt` |
| `AuditLog`（4） | `CaseId` `DocumentNo` `PerformedBy` `PerformedAt` |

1. リスト → 右上の **⚙** → **リストの設定**
2. **インデックスされた列** → **新しいインデックスの作成**
3. 対象の列を選んで **作成**。1列ずつ繰り返す

一覧の絞り込みを SharePoint 側に委任させ、件数が増えても取りこぼさないために必要
（要件定義 15.2）。**データを入れる前にやっておくほうが速い。**

> SharePoint は1リストあたりのインデックス列数が20までなので、最多の
> `SignatureCases`（12列）でも上限内に収まっている。

## 1-5. ライブラリを作る（4つ）

1. サイトのホーム → **＋ 新規** → **ドキュメント ライブラリ**
2. 下表の名前を入れて **作成**

| ライブラリ名 | 用途 |
|---|---|
| `SignatureDocs` | 署名済みPDFの**正本** |
| `SignatureImages` | 手書き署名のPNG |
| `DocTemplates` | PDF生成用の Word テンプレート |
| `WorkTemp` | Word→PDF 変換の中間ファイル（フローが自動削除する） |

### `SignatureDocs` はバージョン管理を有効にする

正本なので、上書き事故から復元できるようにする（要件定義 17.2）。

1. `SignatureDocs` → **⚙** → **ライブラリの設定** → **その他のライブラリ設定**
2. **バージョン設定** → メジャー バージョンを作成する: **はい**（保持数 50 など）

## 1-6. 権限を設定する

[04 権限設計](04-permissions.md) のとおりに設定する。最低限これだけはやる。

1. `SignatureDocs` → ⚙ → ライブラリの設定 → **このドキュメント ライブラリの権限**
   → **権限の継承を中止** → 利用者グループを **閲覧（読み取り）** に変更
   （利用者が正本のPDFを書き換えられないようにする）
2. `SignatureImages` も同様に利用者は閲覧のみ
3. `WorkTemp` は利用者に権限を与えない
4. `SignatureCases` → ⚙ → リストの設定 → **詳細設定** →
   項目レベルのアクセス許可 → **編集アクセス: ユーザーが作成した項目のみ**
   （読み取りアクセスは「すべての項目」のまま。一覧を全員が見られるようにするため）

## 2-1. 組織マスタ 105 件

> **Part 1-2 の方法Aで `data/import/OrgMaster.xlsx` を取り込んだ場合、
> 105件は既に入っているのでこの節は不要。** 件数だけ確認して次へ進む。

方法Bで `OrgMaster` を空のリストとして作った場合は、データを貼り付ける。

1. `data/import/OrgMaster_grid.tsv` をテキスト エディタか Excel で開く
   （タブ区切り。列の順番は `Title` `BranchName` `BlockCode` `BlockName`
   `SiteCode` `SiteName` `SortOrder` の7列。`IsActive` は**入っていない**）
2. `OrgMaster` リストを開き、右上の表示切替から **グリッド ビューでの編集** をオンにする
3. ビューに表示される列の並びを、上記の7列と**同じ順番**にする
   （列見出しをドラッグ、または ビューの編集で並べ替え）
4. TSV のヘッダー行を除いた **105行を選択してコピー**
5. グリッドの1行目・1列目のセルをクリックして **Ctrl+V**
6. `IsActive` は Part 1-3 で既定値を「はい」にしてあるので自動で入る
   （設定していない場合は、貼り付け後に列ごと選択して「はい」にする）

### 投入後の確認

- `OrgMaster` が **105 件**
- `BranchName` が `営業部` / `販売部` / `系統推進部` の3種類
- `BlockName` が **13 種類**（営業部の実ブロック11 ＋ 疑似ブロック2）

> `販売部` と `系統推進部` には元データ（`部門マスタ.xlsx`）にブロックが無いため、
> `販売部（ブロック未設定）` / `系統推進部（ブロック未設定）` を補完している。
> 正式なブロック区分が決まったら、この列を書き換えるだけでよい
> （[07 未確定事項](07-open-issues.md) D-02）。

## 2-2. 確認文面マスタ

**Excel インポートは使わない。** 本文が 3,000 字を超える複数行テキストで、
Excel からリストを作成すると「1行テキスト（255字）」の列が作られて
**本文が切り捨てられる**。確認文面は証跡そのものなので、フォームから入れる。

1. `ConsentMaster` リスト → **＋ 新規**
2. 次のように入力する

| 列 | 値 |
|---|---|
| `Title` | `CANCELFEE-001` |
| `ConsentId` | `CANCELFEE-001` |
| `Version` | `1.0` |
| `EffectiveFrom` | 今日の日付 |
| `EffectiveTo` | 空欄のまま |
| `IsActive` | はい |
| `DisplayTitle` | `分解・診断を伴う整備お見積り後のキャンセル料について` |
| `Body` | 下記 |
| `RevisedBy` | 自分の名前 |
| `RevisedAt` | 今の日時 |

3. `Body` には [`data/consent/ConsentText_v1.0.txt`](../data/consent/ConsentText_v1.0.txt)
   の **3行目以降**（1行目はタイトル、2行目は空行）をコピーして貼り付ける。
   末尾の「私は上記内容について確認いたしました。」まで含める
4. **保存**

### 投入後の確認

- `IsActive` が「はい」の行が **ちょうど1件**であること
  （複数あると適用開始日が最新のものが使われる）
- `Body` の末尾（「私は上記内容について確認いたしました。」）まで入っていること。
  途中で切れていたら列が1行テキストになっている

> ⚠ この文面は元資料「分解・診断を伴う整備お見積り後のキャンセル料について.docx」
> そのままの内容（版 `1.0`、2026-06-02 サービス事業推進部 起案）。
> ただし `整備キャンセル料について.pptx` スライド3に「文面について問題ないか
> ご意見を賜りたい」とあり**上申中**で、社内承認が完了した版ではない。
> 本番運用の開始前に [07 未確定事項](07-open-issues.md) の残課題を確認すること。

## 2-3. 管理者

1. `AppAdmins` リスト → **＋ 新規**
2. `Title` と `UserEmail` に管理者のメールアドレス、`UserName` に名前、
   `IsActive` を「はい」、`Note` に承認者と日付
3. 複数人いる場合は `data/import/AppAdmins_grid.tsv` を書き換えて
   グリッド ビューに貼り付けてもよい（`IsActive` は既定値「はい」で入る）

**まず自分を登録する。** これを入れ忘れると、アプリに削除ボタンが出ない。

`AppAdmins` はアプリ内で削除ボタンを出すかの判定にしか使っていない。
実際に削除できるかは SharePoint の権限で決まるので、
SharePoint 側の管理者グループへの追加も必要（[04 権限設計](04-permissions.md)）。

## 2-4. Word テンプレート

1. `DocTemplates` ライブラリ → **アップロード** → **ファイル**
2. [`templates/整備キャンセル料確認書.docx`](../templates/) を選ぶ

**ファイル名は変えない。** フローがこの名前でテンプレートを指定している。

アップロードしたテンプレートを Word で開くと、`DocumentNo` や `CustomerName` など
16個のコンテンツ コントロール（差し込み欄）が入っているのが見える。
Power Automate の「Microsoft Word テンプレートの入力」がこの名前を入力欄として読む。

## 2-5. 採番カウンタ

`DocumentNumberCounter` には**何も入れない**。
フローが当日分の行を自動で作る。

# Part 3. Power Apps を画面から取り込む

`pac canvas pack` が使えないため、Studio の
**コードのコピー/貼り付け**機能で取り込む。貼り付け用に整形した断片を
[`apps/yaj-cancelfee-signature/paste/`](../apps/yaj-cancelfee-signature/paste/) に
用意してある（`Src/` の内容から自動生成したもの）。

| ファイル | 貼り先 |
|---|---|
| `App-OnStart.txt` | アプリの `OnStart` |
| `<画面名>.controls.yaml` | その画面（コードの貼り付け） |
| `<画面名>.properties.md` | その画面の `Fill` / `OnVisible`（手で入力） |

**この順番でやること。** 順番を変えると、参照先が未作成のためエラーが大量に出る。

## 3-1. 空のアプリを作る

1. [make.powerapps.com](https://make.powerapps.com) → **アプリ** → **新しいアプリ** →
   **キャンバス**
2. 名前: `YAJ 整備キャンセル料 確認書`、形式: **タブレット** → **作成**
3. **設定**（歯車）→ **表示** → **向き: 縦** にする
   → 画面サイズが **768 × 1024** になる。本リポジトリの座標はこの前提
4. **設定** → **全般** → **データ行の制限** を **2000** にする
   一覧のキーワード検索が3列の OR 条件なので、既定の 500 件では取りこぼす

## 3-2. データとフローを接続する

1. 左のメニュー → **データ** → **データの追加** → **SharePoint** →
   サイトの URL を入力 → 接続
2. 次の**7つのリスト**にチェックを入れて **接続**

   `SignatureCases` `OrgMaster` `ConsentMaster` `AppAdmins`
   `SendLog` `AuditLog` `DocumentNumberCounter`

3. **データの追加** → 検索欄に `YAJ-CancelFee` と入力 → 3つのフローを追加

   `YAJ-CancelFee-Submit` `YAJ-CancelFee-Resend` `YAJ-CancelFee-Delete`

> フローがまだ無い場合は Part 4（[flows/](../flows/)）を先にやる。
> フローが無いままだと、`ConsentScreen` `ErrorScreen` `DetailScreen` を貼った時点で
> 「'YAJ-CancelFee-Submit' が見つかりません」というエラーになる。

## 3-3. 画面を6つ作って、正しい名前を付ける

**コントロールを貼る前に、6画面すべてを作って名前を付けておく。**
画面をまたぐ `Navigate()` があるため、貼り付け時に遷移先の画面が存在していないと
エラーになる。

1. 最初からある `Screen1` をダブルクリックして `ListScreen` に改名
2. **＋ 新しい画面** → **空** を5回。それぞれを改名する

   `EditScreen` `ConsentScreen` `CompleteScreen` `ErrorScreen` `DetailScreen`

### 名前は一字一句このとおりにする

`Navigate(ConsentScreen, ...)` のように数式が画面名を直接参照している。
`ConsentScreen1` や `Consentscreen` になっていると、その画面への遷移が全部壊れる。

改名は、ツリー ビューで画面名をダブルクリック、または
右クリック → **名前の変更**。

## 3-4. アプリの `StartScreen` と `OnStart` を設定する

1. ツリー ビュー最上部の **アプリ** を選択
2. 左上のプロパティ選択で `StartScreen` を選び、数式バーに `ListScreen` と入力
3. 同じく `OnStart` を選び、
   [`paste/App-OnStart.txt`](../apps/yaj-cancelfee-signature/paste/App-OnStart.txt)
   の中身を**全部**コピーして数式バーに貼り付ける
4. **アプリ** を右クリック → **OnStart を実行**

この時点で数式バーにエラーが出ていないことを確認する。
出た場合はリストの列名・リスト名の綴りを疑う（Part 1-2 / 1-3）。

## 3-5. 各画面にコントロールを貼り付ける

`paste/README.md` の順（`ListScreen` → `EditScreen` → `ConsentScreen` →
`CompleteScreen` → `ErrorScreen` → `DetailScreen`）で6回繰り返す。

1. `paste/<画面名>.controls.yaml` をテキスト エディタで開き、**全選択してコピー**
2. Studio のツリー ビューで対象の画面を**選択**
3. 画面を**右クリック → コードの貼り付け**
   （右クリック メニューに無い場合は、画面を選択した状態で
   キャンバス上を1回クリックしてから **Ctrl+V**）
4. コントロールが一括で追加される。数式バーのエラー表示を確認する
5. 続けて `paste/<画面名>.properties.md` を開き、
   書かれている `Fill` / `OnVisible` を**その画面自身**に手で入力する
   （画面を選択 → プロパティ ペイン → 詳細設定 → 各プロパティ）

### 貼り付けの順番＝重なり順

YAML の並び順がそのまま Z 順（前面／背面）になる。
一括で貼れば正しい順になるので、**分割して貼らないほうがよい**。

`DetailScreen` は75コントロールあり、貼り付けに数秒かかる。
もし貼り付けが失敗する場合は、YAML の**トップレベルの `- 名前:` の区切り**で
2〜3回に分けて貼る（順番は必ず上から）。

### 「コードの貼り付け」が右クリック メニューに無い場合

Studio の版によっては、**設定 → 近日公開の機能**（または「実験的な機能」）に
コードのコピー/貼り付けに関するトグルがある。オンにして再読み込みする。

それでも出ない場合は、画面を選択して **Ctrl+V** を試す
（クリップボードに YAML があれば取り込まれる）。

## 3-6. 残ったエラーを直す

貼り付け直後に赤いエラーが残る場合、原因はほぼ次の3つ。

| 症状 | 対処 |
|---|---|
| `Distinct(...)` の `Value` が見つからない | `Value` を `Result` に置き換える。Power Fx の版によって `Distinct` の返す列名が異なる。該当は `ListScreen` の `ddFilterBranch` / `ddFilterBlock` / `ddFilterSite` と `EditScreen` の `ddBranch` / `ddBlock` / `ddSite` の計6箇所の `Sort(Distinct(...), Value)` |
| フロー呼び出しの `.Success` が見つからない | Studio の入力候補に出る表記に合わせる。フローの「Power Apps または flow に応答する」で付けた出力名の大文字小文字がそのまま反映される。該当は `ConsentScreen` `ErrorScreen` `DetailScreen` |
| `imgSignature` が画像として扱われない | `Image` プロパティを `varSelected.SignatureImageUrl & ""` にする（テキストであることを明示する） |
| 画面名が見つからない | 3-3 の改名を確認。1文字でも違うと `Navigate()` が壊れる |

## 3-7. 画面の並び順を整える

動作には影響しないが、編集しやすくするため、ツリー ビューで画面をドラッグして
`ListScreen` `EditScreen` `ConsentScreen` `CompleteScreen` `ErrorScreen` `DetailScreen`
の順に並べる。

## 3-8. 保存・公開・共有

1. **保存**
2. **公開** → **このバージョンを公開する**
3. **共有** → 利用者のセキュリティ グループを追加
   - 「共同所有者」には自分以外を2名以上入れる（要件定義 15.5）
   - フローの接続も一緒に共有されることを確認する
